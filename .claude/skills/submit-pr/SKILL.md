## 目的

テストが通っていることを確認してから PR を出す。
PR 本文には人が読んで判断できる情報（何を変えたか・テストは通ったか・受け入れ条件を満たしているか）をすべて含める。

---

## 手順

### Step 1: テストを実行する

```bash
./vendor/bin/sail test
```

- **すべて Pass** → Step 2 へ進む
- **1件でも Fail** → PR を出さない。失敗したテストを報告してユーザーに判断を仰ぐ

### Step 2: 変更内容を把握する

```bash
git log main..HEAD --oneline
git diff main..HEAD --stat
```

対応するイシューがあれば `gh issue view <N>` で受け入れ条件を確認する。

### Step 3: PR 本文を組み立てる

以下のフォーマットに沿って本文を作る：

```
## 変更内容

- <ファイルごとに何を変えたかを箇条書き>

## テスト結果

Tests: <件数> passed (<assertions> assertions) ✅
（deprecated がある場合はその件数と理由も一行で）

## 受け入れ条件との突き合わせ

| # | 受け入れ条件 | 判定 | 対応箇所 |
|---|------------|------|---------|
| 1 | <条件の文言> | ✅ | <ファイル名:行番号 または テスト名> |

（受け入れ条件がないイシューや chore 系変更は「変更内容」だけでよい）
```

### Step 4: PR を作成する

```bash
gh pr create \
  --title "<タイトル>" \
  --body "$(cat <<'EOF'
<Step 3 で組み立てた本文>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

タイトルはコミットの内容を 70 字以内で表す。

---

## 制約

- テストが 1 件でも Fail していたら PR を出さない
- 受け入れ条件の文言はイシューからそのまま写す。言い換えない
- 判定できない条件は ✅ にしない。「未確認」と書いてユーザーに委ねる
